    教程与注意事项
    先看这里：这个功能是做什么的？
    「Cloudflare 后台消息服务」是给需要“关闭网页或离开 UwU 后，仍然希望后台继续执行任务并收到系统通知”的用户使用的。它和上面的「持续运行增强」不是同一种东西：Cloudflare 后台消息服务依靠你自己部署的 Cloudflare Worker；持续运行增强依靠设备端的音频保活。两者可以分别开关，不会因为开启 Cloudflare 后台消息服务就强制播放音频。
    ⚠️ 重要：开启 Cloudflare 后台后，不需要再开启「持续运行增强」（音频保活）。两者请择一使用，不要同时开启！
    Cloudflare 后台就是为了不用音频保活而做的：开了它，就算 UwU 完全关闭也能收到消息，还能一边听音乐一边等回复。两个一起开只会白白耗电、占用音频通道，等于没有用到这个功能。
    隐私与数据流向声明（部署前请先阅读）
    本项目提供的是开源部署代码。按照本教程部署后，Worker、Queue 和 Durable Objects 都建立在你自己的 Cloudflare 帐号中；项目作者的 GitHub 不会因为你部署本项目就自动收到你的聊天内容、API Key、推送订阅或任务记录。当前项目代码没有把这些资料回传到作者的服务器。

    启用 Cloudflare 后台模式时，资料会离开设备：UwU 会把后台任务需要的 userId、聊天识别资料、AI 请求上下文和 AI API 配置（包含 API Key）发送到你自己的 Worker。Worker 会在自己的 Durable Objects 中保存任务和待同步回复等运行资料；Queue 消息本身只包含任务识别资料。Worker 还会把 AI 请求内容发送到你所设置的 AI 服务商，并在自己的 Cloudflare 帐号中保存推送订阅资料以发送通知。

    只开启「持续运行增强」并关闭 Cloudflare 后台模式时：聊天生成请求不会经过这套 Worker、Queue 或 Durable Objects；UwU 会直接把请求发送给你设置的 AI 服务商。

    因此，这不是「资料完全不离开设备」的功能。请只部署到自己控制的 Cloudflare 帐号、使用自己信任的 AI 服务商，并妥善保管 BACKEND_TOKEN、AI API Key 和 VAPID_PRIVATE_KEY；不要使用陌生人的 Worker，也不要把同一个后台 Token 提供给不信任的其他使用者。
    最重要的原则
    你不是把自己的 Cloudflare 帐号交给 UwU，也不是使用别人共用的后台。每个人都应该部署自己的 Worker。下面的教程会从“完全不会 Cloudflare”开始，一步一步告诉你点哪里。
    📖 图文教程
    不想看纯文字的话，可以直接看图文版教程：https://docs.qq.com/doc/DUmh4RU1uRkRQZ3lO
    ① 准备一个 Cloudflare 帐号
    如果你还没有 Cloudflare 帐号，先注册并登录自己的 Cloudflare。进入 Cloudflare 后，在左侧找到 Workers & Pages。

    你只需要使用自己的 Cloudflare 帐号，不需要把 Cloudflare 密码、API Token 或其他登录信息发给任何人。
    ② 先建立 Queue（这一步要在部署 Worker 之前）
    在 Cloudflare 控制台进入左侧 Compute → Queues，点击 Create Queue，名称填写 uwu-ai-jobs 并创建。名称必须完全一致；Queue 不是网址，不用填进 UwU。

    免费额度提醒：Workers Free 的 Queue 每个 Cloudflare 帐号每天共用 10,000 次操作，同一帐号里的其他 Queue 也会占用这份额度。一个成功处理的小消息通常会产生写入、读取、删除共 3 次操作；重试还会增加读取操作。因此约 3,333 个任务／天只是“没有其他 Queue 使用、没有重试”时的理论估算，不能当作保证额度。
    ③ Fork 项目，再用 Cloudflare 连接你自己的 Fork 创建 Worker
    推荐用 Fork 的方式部署：Fork 出来的是你自己 GitHub 账号里的一份副本，以后作者更新了，你可以自己决定什么时候同步，不会被强行更新。

    第 1 步：Fork 项目
    登录 GitHub，打开 https://github.com/YUEYUE0426/background-message-backend，点击右上角的 Fork，再点 Create fork。完成后你的 GitHub 里会出现 你的用户名/background-message-backend。

    第 2 步：在 Cloudflare 连接你的 Fork
    进入 Workers & Pages → Create application → Import a repository（或 Connect to Git），按提示登录并授权 GitHub，选择你自己账号下的 background-message-backend（不是作者的）。

    然后按以下方式填写：
    • Project name：可以保持 background-message-backend
    • Build command：留空
    • Deploy command：填写 npm run deploy
    • Preview command：填写 npx wrangler preview
    • Preview builds：不需要开启
    • Cloudflare Access：不需要开启

    部署成功后，在 Worker 的 Bindings 或 Queue 的 Consumers 页面确认 AI_QUEUE 已连到 uwu-ai-jobs。如果 Worker 之前已部署，先确认 Queue 绑定后再重新部署最新版本。
    ④ 找到你自己的 Worker 地址
    部署成功后，Cloudflare 会给你的 Worker 一个地址，通常类似：
    https://background-message-backend.你的Cloudflare账号.workers.dev

    这个地址就是之后要填进 UwU 的「Cloudflare Worker 地址」。请复制你自己 Cloudflare 页面显示的真实地址，不要照抄教程里的示例。
    ⑤ 打开 /setup，生成 VAPID 密钥
    把刚才的 Worker 地址后面加上 /setup 打开，例如：
    https://你的Worker地址/setup

    打开后会看到「生成 VAPID 密钥」。点击一次即可生成 VAPID_PUBLIC_KEY 和 VAPID_PRIVATE_KEY。

    如果你已经生成并准备使用这一组，就一直使用这一组。
    ⑥ 回到 Cloudflare，打开 Variables and Secrets
    进入：
    Workers & Pages → background-message-backend → Settings → Variables and Secrets

    然后依次添加下面 4 个项目。

    第 1 个：VAPID_PUBLIC_KEY
    Key 填：VAPID_PUBLIC_KEY
    Value 填：刚才 /setup 页面生成的公钥
    Secret：不要开启
    Environment：选择 Production

    第 2 个：VAPID_PRIVATE_KEY
    Key 填：VAPID_PRIVATE_KEY
    Value 填：刚才 /setup 页面生成的私钥
    Secret：必须开启
    Environment：选择 Production

    第 3 个：VAPID_SUBJECT
    Key 填：VAPID_SUBJECT
    Value 填写一个联系方式，格式是 mailto: 加邮箱，例如：mailto:your-email@example.com。这个值只是推送时附带的联系方式，不会真的发邮件，也不影响能不能收到通知，所以填示例值也能正常使用；建议填你自己的邮箱。
    Secret：不要开启
    Environment：选择 Production

    第 4 个：BACKEND_TOKEN（必填）
    Key 填：BACKEND_TOKEN
    Value 使用密码管理器生成一段至少 32 字符的随机值，或用安全的随机密码生成器生成。不要使用示例值、邮箱、Worker 地址或容易猜到的密码。
    Secret：必须开启
    Environment：选择 Production

    保存好这段 Token，下一步要原样填写到 UwU。不要贴到 GitHub、截图或聊天中。

    关于 VAPID_SUBJECT：它不参与密钥生成，只是推送时附带的「联系方式」（格式为 mailto:邮箱 或一个网址）。苹果、Google 等推送服务只会检查格式对不对，不会验证邮箱是否真实，所以直接填示例值也能正常收到通知。建议还是填你自己的邮箱，万一推送出问题，对方可以联系到你。注意要保留开头的 mailto:，不要只写邮箱。它是在生成密钥以后，单独在 Cloudflare 这里填写的。
    ⚠️ 私钥一定要保护好
    VAPID_PRIVATE_KEY 属于敏感信息。不要发到聊天群、GitHub、截图或公开网页里。Cloudflare 里请使用 Secret 保存它。AI API Key 也同样不要公开。
    ⑦ 回到 UwU，填写 Worker 地址和必填 Token
    进入 设置 → API → Cloudflare 后台消息服务，打开开关。

    在「Cloudflare Worker 地址」中粘贴你自己的 Worker 地址，例如：
    https://background-message-backend.你的账号.workers.dev

    在「后台访问 Token」中，原样填写刚才保存在 Cloudflare Secret BACKEND_TOKEN 的同一段值。地址和 Token 都是必填项；没有正确配置 Token，Worker 会拒绝请求。
    ⑧ 先点「测试后台」
    填写 Worker 地址和 Token 后，先不要急着测试通知，先点击 「测试后台」。如果显示连接成功，说明 UwU 已经能够访问你的 Worker。

    如果这里失败，优先检查：
    1. Worker 地址有没有复制错，地址后面有没有误加 /setup；
    2. Cloudflare 的 BACKEND_TOKEN 是否在 Production 环境保存为 Secret；
    3. UwU 中的 Token 是否与 Cloudflare Secret 完全相同；
    4. 最新 Worker 是否已部署并处于 Active 状态。
    ⑨ 注册后台通知
    测试后台连接成功以后，再点击 「注册后台通知」。第一次使用时，系统可能会询问通知权限，请选择允许。

    iPhone 用户特别注意：iOS Web Push 需要把 UwU 添加到主屏幕，然后从主屏幕的 UwU 图标打开，而不是只在 Safari 标签页里使用。添加到主屏幕后，再进入 UwU 完成通知授权和「注册后台通知」。
    ⑩ AI API 还是在 UwU 里管理，不需要搬到 Cloudflare
    这一点非常重要。你的 AI API 地址、API Key、模型等设置，继续在 UwU 的 API 设置里管理。

    以后如果你经常换 API，可以直接在 UwU 里使用「快速 API 设置」或普通 API 设置修改。后台服务会把当前配置同步到你自己的 Worker，不需要每换一次 API 就重新编辑 Cloudflare 项目。

    也就是说：Cloudflare 负责后台执行和通知；UwU 负责管理你正在使用的 AI API 配置。
    ⑪ 第一次测试建议这样做
    完成上面的设置后，确认 Queue 已建立、Worker 部署成功，并在 UwU 完成通知注册。先点 「发送测试通知」：如果 iPhone 收到系统通知，Push 通道正常。再发送一条普通聊天消息，等出现「后台已接收回复任务」提示后切到后台。AI 完成后应收到系统通知；回到 UwU 时会同步回复。

    如果测试通知能收到、但 AI 回复通知收不到，检查 Cloudflare Worker Logs 中的 Queue 与推送错误。
    ⑫ 「持续运行增强」和「Cloudflare 后台消息服务」到底有什么区别？
    持续运行增强：设备端音频保活方案，主要目的是尽量让网页在后台继续保持运行；它可能会带来额外的耗电。

    Cloudflare 后台消息服务：把后台任务交给你自己的 Cloudflare Worker，并通过 Web Push 把消息通知发送回设备；它不需要为了后台功能一直播放音频。

    两者是独立开关，开启 Cloudflare 后台消息服务不会强制开启持续运行增强；但请择一使用，开了 Cloudflare 后台就不需要再开持续运行增强。
    如何更新 Worker（作者发布新版本后）
    1. 打开你自己 GitHub 里 Fork 出来的 background-message-backend 仓库；
    2. 如果页面提示 This branch is out-of-date，点击 Sync fork → Update branch；
    3. Cloudflare 检测到仓库更新后会自动重新部署，等 1～2 分钟，在 Worker 的 Deployments 里看到新的部署记录即可；
    ⚠️ 使用注意事项
    • 只要开启了 Cloudflare 后台，即使在 UwU 前台使用，AI 回复也会通过 Cloudflare 后台完成。
    • 点击「停止」时，如果 AI 服务商已经开始生成，这次的 token 仍会计费，但回复会被丢弃，不会再出现。
    • Cloudflare 免费额度有每日上限，超出后会报错但不会扣费，次日（UTC 0 点）恢复。
    • 不要把 BACKEND_TOKEN、VAPID 私钥、AI API Key 发给任何人。
    ⑬ 如果以后想重新部署怎么办？
    不要重新生成一组 VAPID 密钥后随便覆盖旧值。只要你继续使用同一个 Worker 和原来的 VAPID 配置，就继续使用原来的密钥。只有在你明确需要更换整套推送身份时，才重新生成并同步替换相关配置。
    ⑭ 常见问题
    「/setup」打不开：确认 Worker 已经成功部署，并且访问的是你自己的 Worker 地址加 /setup。

    「测试后台」失败：先检查 Worker 地址、部署状态和是否误把 /setup 填进了 UwU 的 Worker 地址栏。

    能连接 Worker，但收不到通知：先点「发送测试通知」。如果失败，查看 Worker Logs 的推送错误；若提示尚未注册，重新点「注册后台通知」。测试通知成功但 AI 回覆无通知时，确认 Queue 的消费者已连接，并查看 Worker Logs。最后确认 iPhone 允许通知、UwU 从主屏幕打开且专注模式没有过滤通知。

    换了 AI API 后后台还在用旧配置：先回到 UwU，确认新的 API 设置已经保存，再让后台服务同步一次。不要去修改 Cloudflare 里的 AI API Key，因为 AI API 配置本来就是由 UwU 管理的。

    担心 AI Key 安全：后台任务需要在 Worker 端调用 AI，因此当前 AI 配置会同步保存到你自己控制的 Worker。请只连接自己部署的 Worker，不要把 API Key 同步到陌生服务。
    最后给新手宝宝的最短流程：
    ① 登录自己的 Cloudflare 帐号 → ② 先创建 uwu-ai-jobs Queue → ③ Fork 项目并用 Cloudflare 连接你自己的 Fork、确认 Queue 绑定 → ④ 打开 Worker /setup 生成 VAPID 密钥 → ⑤ Cloudflare 添加 Variables/Secrets → ⑥ 回 UwU 填 Worker 地址和必填 Token，并测试连接 → ⑦ 注册后台通知、发送测试通知 → ⑧ iPhone 从主屏幕打开 UwU → ⑨ 正常聊天并切到后台等待回复。记得同一 Cloudflare 帐号其他 Queue 也会共用每日 Queue 额度。

          更新说明

          时间感知

          • 时间感知 char会知道你是几年几月几日几时几分发的消息
          • 更换：移除发送键，原位置改为表情包键，使用输入法的回车键来发送消息，获取ai回复在原位置。

          新增功能

          • 新增：api温度设置
          • 新增：报错弹窗和具体日志
          • 字体移到→自定义界面 增加字体预设管理，调节字体大小，存储空间移至原字体位置（底部dock栏第三个）
          • 新增：发送上下文时自动识别{{user}}字符替换为当前用户人设姓名
          • 新增：后台主动发消息

          双语规则

          • 双语规则改为「」识别而不是（），修改目的：为了让某些char能发带括号的颜文字嗯，过往消息渲染不受影响，也不用怕ai学上下文，在发送过往消息记录之前自动会把（）替换为「」，在写过的扩好输出规范提示词里改一下就行

          界面改版

          • 聊天室UI大改，仿kkt，返回键在左上角，右上角的搜索图标仅为装饰，标题下方的胶囊区域可以给角色分组分类，相当于文件夹，文件夹支持自定义重命名，长按聊天项可以移入文件夹

          聊天设置界面

          • 新增：角色专属状态栏，使用方法和酒馆的状态栏正则一致，最好强调输出在一条消息尽量一个<>标签内完成，不然ai可能会分多条消息发送会掉格式！状态栏卡片可左滑查看历史状态栏，历史状态栏仅保存最近20条
          • 状态栏开启后，聊天界面顶栏备注旁边会显示一个蓝色WIFI信号，当char输出正确的状态栏格式后，点击那个显示状态栏
          • 新增：表情包逻辑，未绑定表情包分组的角色，将不会发送表情包，
          • 新增：头像显示模式，全部显示：每条消息旁边都有个头像。气泡合并：连续消息只显示第一条的消息的头像，Kkt模式：角色的连续消息只显示第一条消息的头像，而我方消息不显示头像。全部隐藏：不显示头像
          • 新增：时间戳开关（仅影响样式），头像圆角自定义，气泡磨砂层开关
          • 修改：引用消息样式仿vx

          • 联系人界面
          • 右上角三图标还没做，仅为装饰
          • 新增：个人档案，在这里显示你的所有人设预设，文本框里可以填通用设定，如：外貌背景巴拉巴拉，点击下方小胶囊可绑定角色，点击已绑定的角色弹出专属设定的输入文本框，填入对这个角色的专属设定（如：正在交往中，是姐姐/妹妹/前女友/角色专属关系和背景），点击保存同步后，自动拼接通用人设+专属人设。使用场景：以一个通用设定绑定多个char，每个char设置不同的专属设定。右上角星星符号，点亮后是选择联系人主界面顶部展示的头像。
